## Hardware and emulator observations

The package installed and RPCS3 launched AIRPLAY02 v0.1.14. During startup, the emulator showed a transient app image while compiling PPU modules. The title returned to the game list after approximately 14 seconds of recorded play time. This is not evidence of stable display output or a clean controller exit.

The capped application log was examined through an allowlisted summary. It recorded:

`APP_START → SCREEN_READY (1280x720) → CONTROLLER_READY → NET_READY → NETCTL_READY → NET_IP_WAIT_START → NET_STATE_WAIT → NET_IP_TIMEOUT → APP_STOP (result 1)`

The log did not reach crypto initialization, RTSP/RTP listener readiness, mDNS, audio initialization, diagnostic tone, or `USER_EXIT_START`. RPCS3 had no usable route for the app's bounded address lookup. Consequently the v0.1.14 SO_REUSEPORT discovery change was not tested. Do not interpret this as an mDNS regression or success.

## FLUSH implementation follow-up

The next source iteration clears buffered data across the FLUSH boundary. Successful RTSP FLUSH clears the bounded RTP queue, drains pending audio UDP datagrams with a fixed cap, resets sequence/retransmission epoch state, and advances a generation. The standalone loop responds by clearing the PCM ring and interpolation history while preserving cumulative metrics. Diagnostics report discarded packet/frame counts and a capped-drain condition.

The full Lima host suite passed after this change, including receiver loopback, RTP queue, PCM ring/resampling, session rejection for idle FLUSH, ALAC, crypto, mDNS, logging, diagnostic tone, and PPU object compilation. The package build for v0.1.15 remains pending.

## Decisions

- Keep v0.1.14 as a structurally valid package, but do not claim its mDNS socket-sharing change works in RPCS3 because route acquisition fails first.
- Use 0.1.15 for the FLUSH fix; avoid repackaging as 0.1.14.
- Keep physical-console files and settings untouched. The current evidence justifies continued host validation, not another console deployment.
