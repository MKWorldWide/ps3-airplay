## Architecture / logic changes

The v0.1.37 candidate includes v0.1.36's peer-checked acceptance of still-playable RTP retransmissions after request bookkeeping expires. The static renderer no longer flips identical buffers continuously. A menu-close invalidation redraws the next inactive buffer, submits one flip, waits asynchronously, and refreshes the other buffer once it is inactive. The periodic screen counter is renamed from `SCREEN_FRAMES` to `SCREEN_FLIPS` to describe actual submissions.

Build and package defaults now advance to release `0.1.37` and SFO `00.37`; production RTSP remains port 5000.

## Runtime behavior changes

Steady state keeps the initialized static image on scanout without continuous flip commands. A menu resume requests a bounded redraw and refresh. Audio may recover some in-window resends that the prior source discarded after tracking expiry. Neither effect has been validated on the PS3 yet.

## Known limitations / follow-ups

The log is wrapped and lacks startup package marker; installed SFO identifies v0.1.35, but the EBOOT was not compared with the local package. The resend improvement is not hardware-tested. Screen flip frequency does not prove flicker causality. Build, RPCS3, PS3, human audio/display, and clean-exit tests remain.

## Risks introduced

The static image may not remain visible or the PS-menu resume path may depend on the old continuous flips. The new event name changes the display diagnostic schema. Late resend acceptance remains bounded by source peer and queue window but may accept sender packets outside tracked requests; existing duplicate, played-sequence, malformed, and queue-full checks still apply.

## Decision record

### Decision: Use v0.1.37 for the next hardware candidate

- **Context:** v0.1.36 was already committed but not installed; installed hardware is still v0.1.35. A display mitigation is also needed.
- **Options considered:** Rebuild v0.1.36 unchanged; skip its audio recovery and only change graphics; combine the committed recovery with a small graphics change in the next patch.
- **Why chosen:** The fresh log's zero recoveries and active underflows match the bounded resend defect already addressed in v0.1.36, while the display loop itself is confirmed to flip continuously.
- **Tradeoffs accepted:** The next test combines two targeted changes, but each has independent counters and user-visible acceptance checks.

### Decision: Stop continuous flips for a static image

- **Context:** A 56.5 Hz flip loop supplies identical image buffers even when the image is unchanged.
- **Options considered:** Keep the loop; alter timing; draw once and refresh after menu resume.
- **Why chosen:** A static framebuffer needs no periodic image change. Resume retains a single redraw/flip and buffer refresh path.
- **Tradeoffs accepted:** The PS3 must verify that the image remains stable and the system menu still resumes correctly.
