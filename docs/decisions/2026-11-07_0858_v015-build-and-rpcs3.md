## Decision record

### Decision 1: Keep the v0.1.15 artifact after an emulator route failure

- **Context:** Package structure and boot succeeded, but address acquisition failed before listener creation.
- **Options considered:** Discard the build; rewrite receiver socket code; preserve the package and repair the emulator test environment.
- **Why chosen:** The app log and RPCS3 error point to route availability before any receiver socket is opened. Changing protocol code would not address this evidence.
- **Tradeoffs accepted:** The package is not a functional audio milestone. Discovery and playback remain untested.

### Decision 2: Advance defaults to v0.1.16

- **Context:** v0.1.15 is built and used in RPCS3; the scripts still defaulted to 0.1.15.
- **Options considered:** Leave defaults at the consumed version and rely on manual overrides; set both defaults to the next unused version.
- **Why chosen:** Defaults should encode the next available package iteration and reduce accidental version reuse.
- **Tradeoffs accepted:** The next build must explicitly document which source changes justify 0.1.16.

### Decision 3: Diagnose network readiness before mDNS

- **Context:** Both v0.1.14 and v0.1.15 stop at `NET_IP_TIMEOUT`; RPCS3 reports `EADDRNOTAVAIL`.
- **Options considered:** Attribute this to SO_REUSEPORT or receiver mDNS; run one bounded test with RPCS3 Internet Connected and restore the previous setting.
- **Why chosen:** The process never reaches socket/listener setup, so the earlier startup boundary must be cleared first.
- **Tradeoffs accepted:** The emulator receives temporary virtual network access; no physical PS3 setting is changed.

## Next recommended step

Run one v0.1.15 RPCS3 test with Internet Connected and restore Disconnected, then continue from the first new readiness or failure event. Keep v0.1.16 as the next package version.
