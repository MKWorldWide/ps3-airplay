## Architecture / logic and runtime changes

A shared 1,536-byte encoded bound admits valid 1,416-byte stereo ALAC without unbounded allocation. Existing larger compressed frames remain packet-size bounded. Gaps split into <=16 chunks; fixed retry/queue/time budgets avoid unbounded traffic. Invalid parse resets stale missing metadata. Interval invalid/retry counters distinguish silent pre-decoder drops.

DRAW state gates image rewriting. A two-second post-resume paced-flip interval gives VSH time to finish composition; both background buffers then restore and presentation returns static. Input/callback polling stays in the existing loop, without added CPU waits.

## Validation and immediate results

Local RTP/jitter/SRC, valid-payload and analyzer cases pass. Presenter mock exercises exact production function bodies: paced settling, static completion and bounded timeout pass. Linux recovery and complete release gate are recorded in the follow-up build report after source commit. No physical console commands issued; current stream preserved.

## Decision record

- Decision: use a shared 1,536-byte encoded cap. Context: valid 1,416-byte ALAC rejected. Options: minimal bound increase, reject normal sender or allocate multi-megabyte full 4,096-sample raw queue. Chosen shared small bound preserves working compressed-frame compatibility and adds ~34 KiB queue storage; larger raw frames remain unsupported.
- Decision: split and retry with strict budgets. Context: >16 holes omitted and successful requests never retried. Options: widen timeout or repair request lifecycle. Chosen fixed queue, >=10ms sends, >=100ms retries, maximum three attempts and one-second tracking lifetime. Tradeoff: additional bounded traffic and duplicate data within retry spans.
- Decision: bounded resume flips plus DRAW tracking. Context: static return may interrupt VSH fade. Options: continuous flipping, global HDMI changes or finite settling. Finite settling preserves static normal operation; two-second duration is a compatibility experiment, not proven compositor synchronization.

## Known limitations / risks

Physical visual/input/audio improvement is unconfirmed. Extra resume flips may cause temporary flicker; extra resends may increase duplicate traffic. Sender-clock mapping, linear SRC fidelity and audio notification scheduling remain unchanged. The audit report describes the former baseline and is historical.
