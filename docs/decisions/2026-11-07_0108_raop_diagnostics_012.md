# Correct the advertised address and add RAOP diagnostics

**Timestamp (EDT):** 2026-11-07 01:08 EST

## Scope of the pass

Prepared package version 0.1.2. The standalone receiver now advertises the PS3 NetCtl IPv4 address after `IPObtained`, adds verbose bounded RTSP/SDP/socket/RTP events, marks diagnostic-log rollover, adds AirTunes-compatible response headers and PAUSE/resume session handling, and labels the mDNS service version 0.1.2. The test build now runs PAUSE/resume and log-wrap checks.

## Why this pass was needed

The iPhone listed the receiver but reported that it could not connect. The available old log had no RTSP accept event, but its package identity and relationship to the tap are unknown. A source review found a plausible issue in selecting the mDNS address through a UDP route toward the multicast group. More detailed event logging is needed to distinguish an address/reachability problem from RTSP negotiation or RTP delivery.

## Architecture / logic changes

The advertised A record now comes from NetCtl's assigned IPv4 address after the state is `IPObtained`; an unspecified or unparsable address stops startup. The verbose build logs an allowlisted RTSP method, response status, state transition, numeric SDP audio properties, socket readiness/failures, connection accept/receive failures, and batched RTP counters. The 16 KiB file emits `LOG_WRAPPED` when it resets. It does not write request bodies, peer addresses, keys, stream payload, or track metadata. RTSP responses now provide `Server: AirTunes/105.1` and `Audio-Jack-Status: connected; type=analog`; OPTIONS includes PAUSE, PAUSE sets the paused state, and RECORD resumes it. The existing AirPort Express compatibility private key was reviewed: it is a published third-party protocol key, not a maintainer/device credential, was present in the repository's initial public commit, and is now identified in third-party notices as outside the MIT code license.

## Runtime behavior changes

Version 0.1.2 reports its package version in the startup log and mDNS TXT record. Network advertisement uses NetCtl state rather than inferred multicast route selection. Diagnostic logs now locate progress through RTSP setup and batched RTP reception while remaining capped. The session can pause and resume without losing the announced stream offer.

## Risks introduced

- Startup now stops if NetCtl does not report `IPObtained` immediately; the existing XMB-connected test setup is assumed, but delayed address acquisition may require a bounded wait/retry.
- The added response headers and pause behavior are standards-informed compatibility choices but still need validation against an actual iPhone sender.
- The new logging macro increases the code included in the package; the file-size cap and privacy fields were host-checked, but console filesystem behavior is not yet hardware-tested.
- The repository contains the well-known AirPort Express protocol key required for legacy RAOP authentication. Its historical public copy cannot be removed from history without an authorized history rewrite; applicable third-party rights remain separate from the project code license.

## Decision record

### Use NetCtl as the address authority

- **Decision:** Advertise the address directly assigned by PS3 NetCtl.
- **Context:** The prior method inferred the local interface by routing a socket toward multicast; the service appeared on the iPhone but failed to connect.
- **Options considered:** Keep the route inference; use a fixed address; query NetCtl.
- **Why chosen:** NetCtl is the platform's assigned network address source and avoids a hardcoded network assumption.
- **Tradeoffs accepted:** Startup currently fails rather than advertising an unverified or zero address if NetCtl is not ready.

### Log protocol stages without packet contents

- **Decision:** Use fixed event names and numeric counters for methods, statuses, states, selected SDP values, socket failures, and RTP batches.
- **Context:** The previous small log could not show whether the sender reached TCP/RTSP, and raw request logging could expose private content.
- **Options considered:** Keep only startup events; log full RTSP traffic; add privacy-safe stage events.
- **Why chosen:** Stage events give actionable failure localization while preserving bounded, shareable logs.
- **Tradeoffs accepted:** Some detail, such as CSeq values and raw SDP, is omitted to avoid high-volume or content-bearing logs.

### Add common response headers and PAUSE/resume transitions

- **Decision:** Add AirTunes server and audio-jack headers and implement the advertised PAUSE method with RECORD resume.
- **Context:** The sender may expect common RAOP response headers and pause support; the state machine previously advertised no PAUSE.
- **Options considered:** Leave responses minimal; add common headers and a bounded transition; claim broader RAOP compatibility.
- **Why chosen:** This is a narrow protocol improvement matching established receiver implementations, with explicit tests.
- **Tradeoffs accepted:** Interoperability is not proven; no broader device compatibility claim is made.

### Label the package 0.1.2

- **Decision:** Use 0.1.2 for the XMB SFO version, package filename, log marker, and service TXT version.
- **Context:** User requested this iteration's version label.
- **Options considered:** Retain the earlier staged package label; use 0.1.1; bump to 0.1.2.
- **Why chosen:** It clearly distinguishes this build from the earlier screen-only candidate.
- **Tradeoffs accepted:** The package has a new exact hash and requires separate transfer approval.
