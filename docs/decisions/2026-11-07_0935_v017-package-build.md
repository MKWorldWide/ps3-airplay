## Decision record

### Decision 1: Use the existing Lima build pipeline for v0.1.17

- **Context:** The source cleanup was committed and pushed, and the recorded PS3DK/PSL1GHT environment is already established in the existing VM.
- **Options considered:** Rebuild on a different host; defer package generation; use the canonical Lima scripts.
- **Why chosen:** It preserves the previously validated ABI/package process and adds no new VM or guest dependency.
- **Tradeoffs accepted:** RPCS3 runtime still depends on desktop UI access; package validation alone is not runtime evidence.

### Decision 2: Keep the RPCS3 network setting unchanged

- **Context:** Prior logs show an address/bind failure in disconnected RPCS3, but no cause is established and a route change is awaiting action-time confirmation.
- **Options considered:** Change the setting now; keep it unchanged and perform the no-network startup check first.
- **Why chosen:** The immediate v0.1.17 display check does not require a network mutation, and the earlier confirmation request has no answer.
- **Tradeoffs accepted:** A receiver startup run may stop at the already observed NetCtl gate until a route test is confirmed.
