# Add an RTSP port override for the RPCS3 bind probe

**Timestamp:** 2026-11-07 06:55 EDT

## Scope of the pass

Add a build-time RTSP listener port input, preserve port 5000 as the default, and prepare v0.1.10 to test port 5001 in RPCS3. Record the v0.1.9 network boundary and update memory/roadmap/test records.

## Why this pass was needed

v0.1.9 showed two distinct outcomes: with RPCS3 network disabled, the new bounded readiness wait timed out; with network enabled, route readiness passed but the RTSP bind still failed. A wildcard host listener occupied TCP 5000 during the connected run, so a host port collision is plausible and can be isolated with an alternate-port test.

## Architecture / logic changes

The standalone app now uses `RAOP_RTSP_PORT` when defined and defaults to 5000 otherwise. The Makefile exposes `RTSP_PORT`, and the Lima build script passes the selected port and records it in the build manifest. The mDNS service already receives `raop_receiver_rtsp_port()`, so it advertises the port that actually bound. Package defaults advance to v0.1.10.

## Runtime behavior changes

No change for a normal build: RTSP still listens on TCP 5000. The RPCS3 probe build will use TCP 5001. UDP audio/control/timing ports remain 6000-6002.

## Immediate results

The network readiness fix has made the unavailable-network boundary explicit. The connected test still fails at TCP listener bind. The host listener on port 5000 is a plausible explanation, not confirmed; the next controlled test changes only the listener port.

- Check `MDNS_READY` and UDP readiness events; do not infer them from TCP readiness alone.
- If 5001 binds, verify whether mDNS discovery and an iPhone RTSP connection can reach it. If it fails, inspect RPCS3 socket logs and host mappings.
- Restore the local RPCS3 Internet status to its original Disconnected value after testing.
- No PS3 hardware test or audible AirPlay stream has been performed in this pass.

## Risks introduced

- A non-default port may not work with every AirPlay sender; DNS-SD advertises the selected SRV port, but real iPhone behavior must be tested.
- A build can accidentally ship with an unintended non-default port if operators leave `RTSP_PORT=5001` in their environment. Keep the script default at 5000 and record the selected port in build metadata.

## Decision record (embedded)

### Decision: Use an explicit build-time port input, default 5000

- **Context:** The emulator host had a TCP 5000 listener during the failed bind; whether this caused the receiver error is unknown.
- **Options considered:** Change the permanent RTSP port; implement automatic fallback; or make the port an explicit build input and conduct a controlled alternate-port test.
- **Chosen:** Add the bounded-scope build input and test port 5001 while keeping default 5000.
- **Tradeoffs:** This avoids speculative runtime fallback and preserves production defaults, but requires a distinct package for the emulator-specific test.

### Decision: Keep the existing mDNS port source

- **Context:** AirPlay discovery must point at the bound port.
- **Options considered:** Duplicate the configured port in discovery code or use the receiver's bound port.
- **Chosen:** Keep passing `raop_receiver_rtsp_port()` into the DNS-SD service.
- **Tradeoffs:** The current control path stays single-source; validate the emitted SRV record for port 5001 in the next test.
