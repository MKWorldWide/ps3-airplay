## Immediate results

The 3,672-byte log has SHA-256 `d51d7fb882e0ddb5dc60cae08449bb1aab4292c59c700ecb0fde5a1b051c0c9f`. It records app startup, pad presence, an early positive report, then `SYSUTIL_MENU_OPEN` without a close. Later input-report counts are zero; there is no raw digital mask transition, START event, or app stop. User reports no buttons work. The log does not prove that the system menu became visible or responsive.

## Known limitations / follow-ups

The exact button order and visible system-menu result were not established. Audio was not retested. The console remains under user control.

## Risks introduced

None; no source, package, or console state changed. The private raw log is not included in the repository.

## Decision record

### Preserve the build and isolate input order before another package

- **Decision:** Do not make a speculative source edit or build a new PKG from this evidence alone.
- **Context:** Manual launch matched the failure, but the log cannot distinguish absent digital input from an open system menu intercepting later input.
- **Options considered:** Change controller polling immediately; test a controlled button sequence; alter console launch state.
- **Why this option was chosen:** A START-first test followed by a separate PS test is a low-risk discriminating observation; remote console actions are unnecessary.
- **Tradeoffs accepted:** Hardware diagnosis requires one more user-observed test before selecting a code fix.

## Next recommended step

On a fresh launch, test START first. If the app stays open, press PS once and confirm separately whether the system menu visibly appears and responds.
