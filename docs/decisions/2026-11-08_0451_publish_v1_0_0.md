## Risks introduced

The validation job receives repository `contents: write` although its API calls are GET-only, because draft release listings are restricted to actors with push access. The token is job-scoped and short-lived; publication mutation remains in a separate job.

## Decision record

### Decision: Publish the verified draft after workflow validation

- **Context:** The exact tag/package evidence and privacy/licensing/build checks passed, and the repaired workflow validated the uploaded draft assets.
- **Options considered:** Leave a verified release as a draft, bypass workflow checks, or publish after the full manual workflow passed.
- **Choice:** Publish only after run `42468858833` completed every validation and publish step, then independently download and hash-check the public package.
- **Tradeoffs accepted:** The Actions validation token needs write permission to inspect draft releases, but the validator performs only reads and the publication mutation stays isolated.
