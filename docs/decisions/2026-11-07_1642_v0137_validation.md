# Validate v0.1.37 and bound hardware claims

**Timestamp:** 2026-11-07 16:42 EDT

## Scope of the pass

Validated the existing v0.1.37 production and RPCS3 packages, installed/launched the RPCS3 variant, ran the bounded synthetic RAOP sender, and recorded the current physical-console access boundary. No source code or PS3 state changed in this pass.

## Why this pass was needed

The v0.1.35 hardware log associated audible dropouts with RTP gaps and active PCM starvation; static-screen flipping was also a plausible contributor to the reported display flicker. The v0.1.37 candidate applies bounded resend acceptance and stops continuous static-image flipping. Evidence was needed before scheduling physical installation.

## Architecture / logic changes

None. The existing candidate keeps the PS3 production listener on TCP 5000 and gives RPCS3 a separate TCP 5001 override. Its display renderer refreshes after menu resume rather than continuously flipping the static image.

## Runtime behavior changes

No new runtime behavior was added in this pass. RPCS3 started v0.1.37, completed its diagnostic tone, and accepted a bounded encrypted RAOP session. It logged an mDNS failure in the emulator environment.

## Validation performed

- Verified production PKG size, SHA-256, and SFO `00.37` from the existing Lima build.
- Verified RPCS3 package size/hash and installed title version `00.37`.
- Installed and launched the emulator package in RPCS3; observed the background image.
- Confirmed RTSP listener readiness on emulator-only port 5001.
- Ran the existing Lima paced sender: OPTIONS, ANNOUNCE, SETUP, RECORD, encrypted RTP, ALAC, and PCM fixture checks reported PASS; receiver log showed successful key unwrap, decryption, ALAC frame decode, and TEARDOWN.
- Read-only direct FTP and webMAN reachability checks failed; no console transfer or installation was attempted.

## Immediate results

The package starts in RPCS3 and processes a synthetic encrypted AirPlay session through RTP decrypt and ALAC decode. The bounded fixture passes without observed loss or decode failure. The emulator log records no recurring screen flips after initial presentation. Physical display stability, PS-menu resume, sustained PCM output, audible dropout rate, and clean console exit remain untested.

## Known limitations / follow-ups

The PS3 endpoint was unreachable from the development host during preflight. The latest physical log and installed identity therefore remain the prior v0.1.35 evidence. Restore reachability and perform a version-matched hardware run before claiming improvement.

## Risks introduced

None in this validation-only pass. Keep the RPCS3 package (port 5001) off-console; deploy the production package (port 5000) only.

## Decision record

### Decision: preserve the current candidate and wait for physical evidence

- **Context:** RPCS3 validates startup and a bounded protocol path, while the reported defects are physical audio/display symptoms.
- **Options considered:** Make another speculative source change; deploy immediately despite failed reachability; preserve v0.1.37 and schedule a controlled hardware retest.
- **Why this option was chosen:** The existing source addresses measured RTP recovery and unnecessary flips; no new emulator failure indicates a concrete defect. Physical validation is currently blocked by network reachability.
- **Tradeoffs accepted:** The reported dropout and flicker are not yet proven fixed; version 0.1.37 remains a candidate pending hardware observations.

## Next recommended step

Reconnect to the console and verify its current app state/version over FTP. Stage the production v0.1.37 PKG using direct FTP, then use webMAN/XMB to install after a safe exit. Compare the v0.1.35 RTP/underflow baseline and verify screen behavior across two menu resumes.
