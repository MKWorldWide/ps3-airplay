# Add Periodic PCM Pipeline Diagnostics

Timestamp: 2026-11-07 09:41 America/New_York (EST)

## Scope of the pass

Added periodic numeric logging for PCM ring occupancy, frames accepted into the ring, frames consumed by the resampler, and frames submitted into GameOS audio blocks. Added bounded conversion of 64-bit counter deltas to the integer event field and reset its baselines at session boundaries. Updated project memory, lessons, roadmap, and test tracking for v0.1.18.

## Why this pass was needed

The existing logger reports underflows and drops but does not provide regular queue level or frame-flow evidence. These values help locate a failure between ALAC decode, PCM buffering, and GameOS block submission, while not proving sound reached the speakers.

## Architecture / logic changes

No audio transport or decoder behavior changed. While an ALAC decoder exists, the main loop emits four bounded, numeric events every five seconds: `PCM_BUFFER_FRAMES` (current occupancy), `PCM_QUEUED_FRAMES` (accepted delta), `PCM_CONSUMED_FRAMES` (ring input frames popped), and `PCM_PORT_SUBMITTED` (48 kHz frames copied into GameOS audio blocks). The event schema remains privacy-safe and log size remains capped at 16 KiB. Counter baselines reset when a recording session starts or ends.

## Runtime behavior changes

During an active ALAC session the capped log gains at most four status records per five seconds. Existing underflow/drop events continue at their existing cadence. `PCM_PORT_SUBMITTED` describes application block submission, not hardware rendering or audible output.

## Risks introduced

The extra event volume may cause the capped log to wrap sooner during long playback. Four events every five seconds are bounded; measure actual log composition during a stream before increasing this cadence.

## Decision record

### Decision 1: Emit low-rate per-stage counters rather than one ambiguous metric

- **Context:** Queue occupancy, decoder output, resampler consumption, and GameOS block submission are separate boundaries.
- **Options considered:** Keep only underflow/drop events; add one overloaded status line; emit separate numeric events with stage-specific names every five seconds.
- **Why chosen:** Separate event names preserve interpretation while the existing logger can remain unchanged and privacy-safe.
- **Tradeoffs accepted:** Four records per interval consume some of the fixed log budget.

### Decision 2: Do not call block submission “rendered” or “audible”

- **Context:** Filling a GameOS audio block does not show that hardware produced sound.
- **Options considered:** Count submissions as rendered frames; label the event as submitted; omit it.
- **Why chosen:** `PCM_PORT_SUBMITTED` accurately reports the application boundary without overstating hardware output.
- **Tradeoffs accepted:** Real audible output still requires a user-confirmed test and/or lower-level device evidence.
