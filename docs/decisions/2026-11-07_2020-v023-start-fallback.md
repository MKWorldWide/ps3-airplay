# Route normalized START input to app exit

**Timestamp:** 2026-11-07 20:20 EDT

## Scope of the pass

Fix the standalone app's START action to use the normalized controller button mask, and advance package defaults to v0.2.3 / SFO 00.43.

## Why this pass was needed

The user confirmed PS was pressed first and the PS system menu never appeared visibly. Source inspection showed that the controller code normalized START from both PSL1GHT's `BTN_START` field and raw `PAD_CTRL_START`, but the exit action still checked only `data.BTN_START`. This concrete wiring gap could ignore the raw fallback.

## Architecture / logic changes

The pad poller already maps controller inputs into a normalized bitmask. START exit dispatch now checks bit zero of that mask rather than bypassing it to inspect only the PSL1GHT field. The existing standard-field behavior remains, while raw-mask START is now eligible to exit as intended.

## Runtime behavior changes

If the controller reports START through either decoded representation, the app requests normal cleanup and return to XMB. PS-menu behavior is unchanged.

## Validation performed

- Inspected `poll_controls`: both standard and raw START are ORed into the normalized bit zero; the old action condition inspected only `data.BTN_START`.
- Updated the PPU build and packaging defaults to app `0.2.3` and SFO `00.43`.
- Source build, package validation, and hardware tests are pending this source commit.

## Immediate results

Source now routes normalized START to the existing exit path. No PS3 state was changed in this pass.

## Known limitations / follow-ups

The v0.2.2 run has no digital-mask transition in its retained log, so it does not establish that the controller supplied START data. The user confirmed the PS menu was never visible after pressing PS first. That separate menu problem remains unexplained. Build v0.2.3, validate the package, then test START first on hardware.

## Risks introduced

The change is narrowly scoped. If the raw mask constant or data layout is incorrect for the connected controller, the new path will not trigger; the hardware test is required. No console files or system settings changed.

## Decision record

### Use the normalized input state for START dispatch

- **Decision:** Test the normalized START bit in the exit action.
- **Context:** The raw-mask fallback was already present in decoding but was not connected to the action.
- **Options considered:** Remove the raw fallback; change controller polling broadly; route the existing normalized state to the action.
- **Why this option was chosen:** It completes the existing design with a one-line change and keeps the standard and fallback paths consistent.
- **Tradeoffs accepted:** Does not explain why the PS menu failed to appear and depends on a hardware report containing digital input.
