## Decision record

### Decision 1: Generate v0.1.16 from the committed source revision

- **Context:** The volume implementation was committed and host-tested; the prior ELF was a pre-commit working-tree build.
- **Options considered:** Stop at the working-tree ELF; package the exact pushed source; wait for an RPCS3 session first.
- **Why chosen:** The project needs a reproducible artifact tied to its commit before runtime validation.
- **Tradeoffs accepted:** Package generation consumes v0.1.16 even though RPCS3 installation is pending.

### Decision 2: Convert the background on the host rather than add guest dependencies

- **Context:** Lima lacks Pillow, but the checked-in converter is deterministic and host Pillow is already available.
- **Options considered:** Install Pillow into Lima; use a different untracked converter; run the repository script on the host and verify byte count.
- **Why chosen:** It preserves the existing build process and avoids modifying the lean guest environment.
- **Tradeoffs accepted:** The generated RGB file must be copied into the guest build directory before packaging.

### Decision 3: Defer RPCS3 installation until the UI can be accessed

- **Context:** The computer-use session could not access the RPCS3 UI.
- **Options considered:** Change the emulator installation through an alternate UI path; wait for manual unlock while recording the validated artifact.
- **Why chosen:** The requested computer-use install/run workflow requires the desktop UI and the UI is unavailable; package generation and documentation were still independently verifiable.
- **Tradeoffs accepted:** No RPCS3 startup result exists for v0.1.16 yet.
